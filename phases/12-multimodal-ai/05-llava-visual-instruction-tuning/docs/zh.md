# LLaVA and Visual Instruction Tuning · LLaVA 与视觉指令微调

> LLaVA（2023 年 4 月）是这颗星球上被照抄得最多的多模态架构。它用一个 2 层 MLP 换掉了 BLIP-2 的 Q-Former，用朴素的 token 拼接换掉了 Flamingo 的门控 cross-attention，然后在 GPT-4 从纯文本 caption 生成的 158k 轮视觉指令上训练。2023 到 2026 年间，每一个动手造 VLM 的从业者，造的都是某种 LLaVA 变体。LLaVA-1.5 加了 AnyRes，LLaVA-NeXT 提升了分辨率，LLaVA-OneVision 用同一套配方统一了图像、多图和视频。本课解读这套配方、实现 projector，并解释「简单为什么赢了」。
>
> LLaVA (April 2023) is the most copied multimodal architecture on the planet. It replaced BLIP-2's Q-Former with a 2-layer MLP, replaced Flamingo's gated cross-attention with naive token concatenation, and trained on 158k visual-instruction turns generated by GPT-4 from text-only captions. Any practitioner who built a VLM between 2023 and 2026 built some variant of LLaVA. LLaVA-1.5 added AnyRes. LLaVA-NeXT bumped resolution. LLaVA-OneVision unified image, multi-image, and video in one recipe. This lesson reads the recipe, implements the projector, and explains why "simpler won."

## The Problem · 问题在哪

BLIP-2 的 Q-Former（12.03 课）把一张图像压缩成 32 个 token。干净、高效、跑分好看。但它有两个问题。

第一，Q-Former 可训练，但它的损失不是最终任务。阶段 1 训 ITC+ITM+ITG，阶段 2 训 LM 损失。query 学到的是某种中间表示，LLM 之后还得去解码它。信息在瓶颈处流失。

第二，Q-Former 要 1.88 亿参数，而且在 LLaVA 的 2023 年规模下，你必须与目标 LLM 联合设计它。换 LLM，重训 Q-Former；换视觉编码器，重训。每一种组合都是一个独立的研发项目。

LLaVA 的答案简单得让人不好意思：拿 ViT 的 576 个 patch token，每个过一个 2 层 MLP（`1024 → 4096 → 4096`），把 576 个全部倒进 LLM 的输入序列。没有瓶颈，没有在奇怪目标上的阶段 1 预训练，直接用 LM 损失训练这个 MLP。

数据从哪来？LLaVA 的第二个洞见：用 GPT-4（纯文本）生成指令数据。把一张图的 COCO caption 和边界框数据喂给 GPT-4，让它生成对话、描述和复杂推理问题。白得 158k 轮指令-回复。零人工标注。

结果：一个在 8 块 A100 上跑了一天的 VLM，在 MMMU 上击败 Flamingo，并发布了社区可以扩展的开源 checkpoint。到 2023 年底，它已经衍生出 50 多个分叉。

> BLIP-2's Q-Former (Lesson 12.03) compresses an image to 32 tokens. Clean, efficient, good for benchmarks. But it has two problems.
> First, the Q-Former is trainable but its loss is not the final task. Stage 1 trains ITC+ITM+ITG. Stage 2 trains LM loss. The queries learn some intermediate representation that the LLM then has to decode. Information is lost in the bottleneck.
> Second, the Q-Former takes 188M params, and at LLaVA's 2023 scale you had to co-design it with your target LLM. Change the LLM, retrain the Q-Former. Change the vision encoder, retrain. Every combination was a separate R&D project.
> The LLaVA answer was embarrassing in its simplicity: take the ViT's 576 patch tokens, pass each through a 2-layer MLP (`1024 → 4096 → 4096`), and dump all 576 into the LLM's input sequence. No bottleneck. No stage 1 pretraining on weird objectives. Just train the MLP on a direct LM loss.
> Where does the data come from? LLaVA's second insight: use GPT-4 (text-only) to generate instruction data. ... 158k instruction-response turns for free. No human annotation.
> The result: a VLM that ran on 8 A100s for one day, beat Flamingo on MMMU, and shipped an open checkpoint the community could extend. By late 2023 it had spawned 50+ forks.

## The Concept · 核心概念

### The architecture · 架构

13B 的 LLaVA-1.5：

- 视觉编码器：CLIP ViT-L/14 @ 336（阶段 1 冻结，阶段 2 可选解冻）。
- Projector：带 GELU 激活的 2 层 MLP，`1024 → 4096 → 4096`。
- LLM：Vicuna-13B（后来是 Llama-3.1-8B）。

对一张图 + 文本 prompt 的前向过程：

```
img -> ViT -> 576 patches of dim 1024
patches -> MLP -> 576 tokens of dim 4096
prompt: system + "<image>" placeholder + user question
replace <image> token with the 576 projected tokens
feed the full sequence to the LLM
decode response
```

图像占据 LLM 上下文中的 576 个 token。在 2048 上下文里，文本还剩 1472 个 token；在 32k 上下文里，它只是舍入误差。

> LLaVA-1.5 at 13B: ... The image occupies 576 tokens of the LLM context. At 2048 context, that leaves 1472 tokens for text. At 32k context, it is a rounding error.

### Stage 1: projector alignment · 阶段 1：projector 对齐

冻结 ViT。冻结 LLM。只训练 2 层 MLP。数据：558k 图文对（LAION-CC-SBU）。损失：在投影后的图像 token 条件下，对 caption 做语言建模。

batch 128 下，一个 epoch 几个小时就能跑完。projector 学会把 ViT 空间映射到 LLM 空间。没有任何任务特定的监督。

> Freeze ViT. Freeze LLM. Train only the 2-layer MLP. Dataset: 558k image-caption pairs (LAION-CC-SBU). Loss: language modeling on the caption, conditioned on the projected image tokens.
> In a single epoch at batch 128 this is done in a few hours. The projector learns to map ViT-space to LLM-space. No task-specific supervision.

### Stage 2: visual instruction tuning · 阶段 2：视觉指令微调

解冻 projector（保持可训练）。解冻 LLM（通常全量，有时 LoRA）。在 158k 视觉指令轮次上训练。

指令数据才是窍门。Liu 等人这样生成它：

1. 取一张 COCO 图像。
2. 提取文本描述（5 条人工 caption + 边界框列表）。
3. 用三个 prompt 模板发给 GPT-4：
   - 对话：「针对这张图，生成一段用户与助手之间的往返对话。」
   - 详细描述：「给这张图一个丰富、细致的描述。」
   - 复杂推理：「提一个需要针对图像推理的问题，然后回答它。」
4. 把 GPT-4 的输出解析成（instruction, response）对。

以上没有任何一步直接碰图像——只碰文本描述。GPT-4 会幻觉出貌似合理的图像内容。有一些噪声，但它管用：158k 轮就足以解锁对话能力。

> The instruction data is the trick. Liu et al. generated it by: 1. Take a COCO image. 2. Extract the text description (5 human captions + bounding-box list). 3. Send to GPT-4 with three prompt templates: ... 4. Parse GPT-4's output into (instruction, response) pairs.
> None of this touches the image directly — only the text description. GPT-4 hallucinates plausible image content. Some noise, but it worked: 158k turns was enough to unlock dialogue.

### Why the community copied this · 社区为什么照抄

- 没有为阶段 1 单独调的损失。从头到尾都是 LM 损失。
- projector 以小时计训练，不以天计。
- LLM 可以换（LLaVA-Llama2、LLaVA-Mistral、LLaVA-Llama3），只需重训 projector。
- 视觉指令数据管线用的是 GPT-4，为新领域重新生成很便宜。

> - No stage-1-specific losses to tune. LM loss throughout. ... - Visual-instruction data pipeline uses GPT-4 and is cheap to regenerate for a new domain.

### LLaVA-1.5 and LLaVA-NeXT · LLaVA-1.5 与 LLaVA-NeXT

LLaVA-1.5（2023 年 10 月）增加了：

- 学术任务数据（VQA、OKVQA、RefCOCO）混入指令微调。
- 更好的 system prompt。
- 上下文从 2048 → 32k。

LLaVA-NeXT（2024 年 1 月）增加了：

- AnyRes：把高分辨率图切成 2x2 或 1x3 的 336x336 crop 网格，外加一张全局低清缩略图。每个 crop 变成 576 个 token；每图总计约 2880 个视觉 token。OCR 和图表任务大涨。
- 更好的指令数据配比，加入 ShareGPT4V（高质量 GPT-4V caption）。
- 更强的基础 LLM（Mistral-7B、Yi-34B）。

> LLaVA-1.5 (October 2023) added: ... LLaVA-NeXT (January 2024) added: - AnyRes: split high-res images into a 2x2 or 1x3 grid of 336x336 crops, plus one global low-res thumbnail. Each crop becomes 576 tokens; total around 2880 visual tokens per image. OCR and chart tasks jumped. ...

### LLaVA-OneVision · LLaVA-OneVision

12.08 课会深入 OneVision。简短版：同一个 projector，但训练时用一套课程，让单个模型在共享的视觉 token 预算下覆盖单图、多图和视频。

### The comparison to Q-Former · 与 Q-Former 对比

| | Q-Former (BLIP-2) | MLP (LLaVA) |
|---|---|---|
| 每图视觉 token | 32 | 576（基础）或 2880（AnyRes） |
| 可训练参数 | 188M + LM | 40M + LM |
| 阶段 1 损失 | ITC+ITM+ITG | 只有 LM |
| 换 LLM | 需要重训 | 极小重训即可更换 |
| 多图 | 别扭 | 自然（拼接） |
| 视频 | 别扭 | 自然（逐帧拼接） |
| Token 预算 | 小 | 大 |

MLP 赢在简单和 token 灵活性。Q-Former 赢在 token 预算。到 2023 年底，token 预算不再是紧约束（LLM 上下文涨到了 32k-128k+），简单性占了上风。

> MLP wins on simplicity and token flexibility. Q-Former wins on token budget. By late 2023 the token budget was no longer the binding constraint (LLM contexts grew to 32k-128k+) and simplicity dominated.

### The prompt format · Prompt 格式

```
A chat between a curious human and an artificial intelligence assistant. The assistant gives helpful, detailed, and polite answers to the human's questions. USER: <image> Describe this image in detail. ASSISTANT: The image shows ...
```

`<image>` 是一个占位符 token。在分词之前，它被替换成 576 个视觉 token（AnyRes 下是 2880 个）。分词器看到的序列比它训练时的略长，但 LLM 能处理这种新输入，因为阶段 1 教会了它。

> `<image>` is a placeholder token. Before tokenization, it is replaced with the 576 visual tokens (or 2880 with AnyRes). Tokenizer sees a slightly longer sequence than it was trained on, but the LLM handles the novel input because stage 1 taught it to.

### Parameter economy · 参数经济学

LLaVA-1.5-7B 的拆解：

- CLIP ViT-L/14 @ 336：303M（阶段 1 冻结，阶段 2 常常解冻）。
- Projector（2 个线性层）：约 22M 可训练。
- Llama-7B：7B。
- 总计：7.3B 参数。阶段 2 可训练：整个 7B + 22M projector。

阶段 2 的训练成本：8xA100 上约 20 小时。这是关键数字——一天、一个节点、可复现。这就是 LLaVA 传播开来的原因。

> LLaVA-1.5-7B breakdown: ... Training cost for stage 2: ~20 hours on 8xA100. This is the key number — one day, one node, reproducible. That is why LLaVA spread.

## Use It · 实战用法

`code/main.py` 实现：

1. 2 层 MLP projector（玩具规模 16 维 → 32 维 → 32 维），纯 Python。
2. prompt 构建管线：system prompt + 被替换成 N 个投影 token 的 `<image>` + user 轮次 + assistant 生成占位。
3. 一个可视化器：展示 576 token 的视觉块在 LLM 上下文里的样子（占 2k / 32k / 128k 上下文的百分比）。

> `code/main.py` implements: 1. The 2-layer MLP projector (dim 16 → 32 → 32 for toy scale) in pure Python. 2. The prompt-building pipeline: system prompt + `<image>` replaced with N projected tokens + user turn + assistant generation placeholder. 3. A visualizer for what the 576-token visual block looks like in LLM context (percentage of 2k / 32k / 128k context consumed).

## Ship It · 交付

本课产出 `outputs/skill-llava-vibes-eval.md`。给定一个 LLaVA 系 checkpoint，它运行一套 10 条 prompt 的 vibes-eval（3 条 captioning、3 条 VQA、2 条推理、2 条拒答）并输出人类可读的记分卡。这不是基准测试；是确认 projector 与 LLM 连接良好的冒烟测试。

> This lesson produces `outputs/skill-llava-vibes-eval.md`. Given a LLaVA-family checkpoint, it runs a 10-prompt vibes-eval suite (3 captioning, 3 VQA, 2 reasoning, 2 refusal) and reports a human-readable scorecard. Not a benchmark; a smoke test to confirm the projector and LLM are connecting well.

## Key Terms · 术语表

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Projector | "MLP 桥" | 带 GELU 的 2 层 MLP，把 ViT 维度映射到 LLM 维度 |
| Image token | "&lt;image&gt; 占位符" | 推理前被替换成 N 个投影视觉 token 的 prompt 标记 |
| Visual instruction tuning | "LLaVA 阶段 2" | 在 GPT-4 生成的（图像, 指令, 回复）三元组上训练 |
